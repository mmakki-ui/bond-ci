# THIS FILE IS A RENDERING, NOT A SOURCE.
# ======================================
# Round 2 hand-wrote these columns and nothing checked them, so a fabricated pass
# count was invisible: moving S3.thr to UNGATED with a made-up "9/14" passed the
# whole self-test. Every column here is DERIVED --
#   `ladder_replay.measure(pathsim.py, ladder_ci_runs.json)` replays each recorded
#   run through pathsim's real verdict()/bars source and recomputes the threshold
#   text, the pass count, the envelope and the hold-out audit --
# and `ladder_equiv_check.py` asserts this file reproduces that derivation exactly,
# fatally, on every CI run. Editing a number here without the runs backing it is a
# CI failure. Regenerate, do not hand-patch:
#     python p4-bondagg/sim/ladder_equiv_check.py --emit-record
#
# Regenerate the RUNS (ladder_ci_runs.json) after ANY change to pathsim.py's bars
# or to p4-bondagg/daemon, and say in the commit what changed and why.
# Reproduce a row:  gh api repos/<repo>/actions/jobs/<ladder job id>/logs
#
# COLUMNS -- pipe-delimited, and the delimiter is load-bearing: round 2 split on
# whitespace, which is ambiguous for `tail900 >= 1871.5 of 1900` and `K in {8,12}`.
#   bar | threshold | pass/den | envelope | hold-outs
#   threshold : BYTE-EQUAL to the `bar=` text pathsim prints. ladder_gate.py
#               compares the two on every run -- that is what makes a diluted
#               threshold (`delivered >= 1800` -> `>= 1`) fail the job instead of
#               being printed next to this envelope as though nothing happened.
#   pass/den  : the CLASS is derived from this and checked against it. den/den
#               GATED, 0/den KNOWN HONEST FAIL, anything between UNGATED.
#   envelope  : `min <x> max <y>` (numeric bars) or `tokens {a,b}`. Source of the
#               fatal DRIFT band [min-(max-min), max+(max-min)] -- derived from
#               MEASURED VALUES, so it survives a diluted threshold. `min == max`
#               means the record established no spread and NO band exists; those
#               four bars (S1.loss, S1.share, S4.loss, S4.tail) are named
#               non-coverage, carried by their threshold alone.
#   hold-outs : the band's own false-positive audit, and the column exists
#               because round 3 asserted it in prose and overstated it. For each
#               recorded value, build the band from the OTHERS and ask whether the
#               held-out value falls inside.
#                 holdouts    -- hold-outs that HAD a band to test against
#                 informative -- of those, the ones that actually MOVED the band
#                                (unique min or unique max). Any other hold-out is
#                                inside by construction and tests nothing.
#                 excluded    -- hold-outs the band rejects: a measured false
#                                positive of the fatal DRIFT check.
#                 skipped     -- no band derivable from the others; not a pass.
#               `informative 0` means the bar's band has never been tested at all,
#               however large its `holdouts` number looks. S6.k and S7.k read
#               `informative 0` here. On the 14-run record S5.loss did too -- and
#               S5.loss is the bar that then reddened the fatal job.
#
# WHAT THE SMALL WINDOW HID. Six bars' 14-run maxima were exceeded once the
# population was collected: S5.loss 0.10 -> 1.70, S6.loss 1.70 -> 2.60,
# S7.loss 3.83 -> 4.43, S8.loss 4.23 -> 4.63, S2.loss 8.43 -> 9.43,
# S3.peerloss 33 -> 39. An observed max is a DESCRIPTION, never a bound. That is
# the standing argument against widening any UNGATED bar to its observed max
# (U39a), and it is now an argument from 69 runs rather than from 14.
#
