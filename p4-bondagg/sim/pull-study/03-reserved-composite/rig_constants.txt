  N5-corr     5       29.0       90.0     130.0     249.0     249.0    52.2%       no

  Both MEASURED terms are ORDER STATISTICS over the link set, so both are
  non-decreasing in N by construction -- adding a link can only widen the owd
  spread and can only raise max(jit).  That much is N-generic in FORM.
  What is not: the +130 ms is the LARGEST term at every N in the table, so the
  hold is majority-constant everywhere the rig has ever run.
  WIDEST mix the archetype set can build (all five, any N>=5): raw=249.0 ms,
  ceiling=350 ms.  The ceiling is UNREACHABLE with these archetypes at ANY N --
  max/min are set by the archetype SET, not by how many links are drawn from it,
  so duplicating links cannot widen it.  Nothing in the rig ever exercises either
  clamp: they are untested code at every N the battery runs.

  cellA / eth physical knobs           [OPEN]
    does : the rig's two original paths: cap base/amp/period, loc/down owd, jit, the dropout schedule, local_mult
    evidence: C1: byte-identical to ackclock_sim.make_defs at every tick (delta 0 on all seven
      quantities). cellB, cellC and wifi have no ancestor. ADR-004 condition 2 is open, so not one of
      them has ever been measured against hardware at ANY N.

  target_ms = 40.0                     [N-INVARIANT (measured)]
    does : per-link admission ms-gate and delivered-rate meter threshold; read by Dc, ewma, pull and oracle
    evidence: C4: the loss-optimal value is 30/30/20/30 ms at load 0.65 and 30/40/40/40 ms at 0.95,
      for N=2,3,4,5 respectively. It tracks OFFERED LOAD, not link count -- so the same number is
      right at N=5 as at N=2. Separate, and NOT an N defect: 40 is not the optimum at 0.65. Left
      exactly as it is.

  reorder hold, the +130.0 ms term     [OPEN]
    does : additive term of the ring release timeout, and of the Dc duplicate TTL
    evidence: C2: the largest of the three terms at every N (52-58 percent of the raw value). C3: the
      formula returns 223-249 ms while the loss optimum is 840-1000 ms; the gap is 602-777 ms and does
      not close as N grows. A LEVEL error the rig cannot derive -- ROADMAP U13 owns the derivation. Do
      NOT substitute another number.

  hold: 3.0 * max(jit)                 [DERIVABLE in form, OPEN in value]
    does : 3-sigma jitter margin, taken from the single highest-jitter link
    evidence: C2: an order statistic over the link set, so N-generic in shape. But it is anchored on
      the max-jitter link, which need not be either of the two extremal-OWD links whose arrival skew
      it is margining -- at N=2 they coincide and from N=3 they need not. ackclock_sim.py:614-620
      already carries the derived shape (0.5 * measured RTTmin spread + 3 * measured sigma); it is
      reachable only under sched=="C" and the gated set never runs it.

  hold clamps 0.08 / 0.35 s            [OPEN]
    does : floor and ceiling on the same hold
    evidence: C2: the widest mix the archetype set can build gives raw 249 ms, so NEITHER clamp is
      reachable at ANY N -- they are untested code on every run the battery has ever made. C3: the
      loss optimum is 840-1000 ms, 2.4-2.9 times ABOVE the 350 ms ceiling, so the ceiling is not
      dormant on the loss axis. It caps the answer.

  maxq_ms = 300.0 -> 0.3 * sum(cap0)   [DERIVABLE]
    does : shared-pool byte bound
    evidence: Already N-generic in form: a delay bound times the AGGREGATE nominal rate, linear in N
      by construction. Two caveats to carry: cap0 is cap_fn(0.0), which is U33's finding F1; and U7's
      shipped Go pool bound derives from sum(SO_SNDBUF) instead (ROADMAP, U7 round 2), so the rig and
      the artifact bound the same pool by DIFFERENT quantities. That divergence belongs to U9 / EQ-1.

  QMAX_MS = 300.0                      [N-INVARIANT in form, OPEN in value]
    does : per-path downstream fluid tail-drop bound
    evidence: Per-link; no N term appears anywhere it is used. Its VALUE has never been measured on
      hardware (ADR-004 condition 2).

  NLAG = 0.350 + the 0.100 s window    [N-INVARIANT in form, OPEN in value]
    does : per-link lagged delivered-rate meter window
    evidence: Per-link; no N term. It is a hardware RTT-scale quantity, and G1 is what measures it.

  deliv_hist horizon = 0.6 s           [DERIVABLE]
    does : per-link delivered-history trim
    evidence: _lagged_deliv reads [now-NLAG-0.100, now-NLAG), so the horizon must exceed NLAG + 0.100
      = 0.450 s or the meter reads an empty window. The requirement is exact and derivable from the
      module; the remaining 0.150 s of margin is not.

  DRAIN_TAU = 0.10 / REGEN = 0.02      [OPEN]
    does : per-link local drain EWMA and idle probe-up toward cap0; feeds _local_ms and therefore Dc's room() gate
    evidence: Per-link and N-independent in form, but no derivation exists on the record for either
      value.

  HEALTH_FRAC = 0.75                   [NOT LIVE for the gated set]
    does : host must be draining at least 75 percent of its nominal cap0
    evidence: reserved_composite.py:298 sends Dc and Dpp down the meter branch; HEALTH_FRAC is read
      only at :311, inside the D / D-prime else-branch. It gates nothing this CI job scores. Reported
      so it is not mistaken for a live N=2 constant.

  tshare = assigned[0] / sum           [DERIVABLE]
    does : a PER-LINK metric keyed to INDEX 0, in the rig and in the oracle alike
    evidence: C5: exact at N=2, because index 0 IS the only spotty link there, and wrong by
      0.097-0.223 from N=3. The N-generic form already exists -- highn_battery.py:196 computes the
      share over spotty_idx and reduces to tshare at N=2. The battery is clean; the METRIC and its
      three downstream citations are not.

  cap0 = cap_fn(0.0)                   [DERIVABLE]
    does : each path's NOMINAL cap, read in nine places
    evidence: U33's finding F1: nominal is sampled from the trace at one instant rather than being a

      maxq_kb, drain_ewma, push_est and REGEN, so it belongs in this table.
